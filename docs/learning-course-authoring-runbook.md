# Growvelt Learning course authoring foundation runbook

## Scope

`202608090004_course_authoring_foundation.sql` establishes only approved-Instructor course draft metadata. It does not add curriculum, lessons, video, resources, submissions, publishing, payments, enrollments, Storage, or learner access.

The migration replaces legacy browser course-insert/update policies with four authenticated, `SECURITY DEFINER` RPCs:

- `create_instructor_course_draft(...)`
- `update_instructor_course_draft(...)`
- `list_own_instructor_courses(integer, integer)`
- `get_own_instructor_course(bigint)`

Each checks `auth.uid()` and `is_approved_growvelt_instructor()`, fixes `search_path`, and derives ownership from the authenticated user. Browser callers cannot supply `instructor_id`, `status`, `slug`, publication state, or limited-time-free state.

## Preconditions

Before execution, use the Supabase SQL editor with an owner-approved migration workflow and confirm:

1. The Phase 1 authorization and Instructor-review migrations have been applied.
2. `learning_courses` has the existing bigint ID, UUID `instructor_id`, unique text `slug`, price/free fields, timestamps, and lifecycle of `draft`, `pending_review`, `published`, and `archived`.
3. RLS is enabled on `learning_courses`.
4. The published-read policy, legacy authenticated `INSERT`/`UPDATE` grants, and the three expected legacy Instructor policies exist exactly as named. The expected baseline has no explicit browser column mutation ACLs; if any are found, the migration reports and revokes them.
5. `is_approved_growvelt_instructor()` exists and is `SECURITY DEFINER`.
6. No Phase 2A-A RPC exists already.

The migration performs these guards and runs inside one transaction. A failure must be investigated; do not edit the migration to force it through an unexpected partial state.

## Execution order

1. Review the migration in Git against the deployed schema.
2. Take the normal Supabase schema backup/export appropriate to the production maintenance process.
3. Run the migration once.
4. Verify the SQL below before deploying the application source.
5. Deploy the matching application source only after verification passes.

## Verification SQL

```sql
select policyname, cmd
from pg_policies
where schemaname = 'public'
  and tablename = 'learning_courses'
order by policyname;

select routine_name, security_type
from information_schema.routines
where routine_schema = 'public'
  and routine_name in (
    'create_instructor_course_draft',
    'update_instructor_course_draft',
    'list_own_instructor_courses',
    'get_own_instructor_course'
  );

select has_function_privilege('anon', 'public.create_instructor_course_draft(text,text,text,text,text,boolean,numeric,text)', 'EXECUTE') as anon_can_create,
       has_function_privilege('authenticated', 'public.create_instructor_course_draft(text,text,text,text,text,boolean,numeric,text)', 'EXECUTE') as authenticated_can_create,
       has_table_privilege('authenticated', 'public.learning_courses', 'INSERT') as authenticated_can_insert,
       has_table_privilege('authenticated', 'public.learning_courses', 'UPDATE') as authenticated_can_update;

select coalesce(grantee.rolname, 'PUBLIC') as grantee,
       attribute.attname as column_name,
       column_acl.privilege_type
from (
  select attribute.attname, attribute.attacl
  from pg_attribute as attribute
  where attribute.attrelid = 'public.learning_courses'::regclass
    and attribute.attnum > 0
    and not attribute.attisdropped
    and attribute.attacl is not null
) as attribute
cross join lateral aclexplode(attribute.attacl) as column_acl
left join pg_roles as grantee on grantee.oid = column_acl.grantee
where column_acl.privilege_type in ('INSERT', 'UPDATE')
  and (column_acl.grantee = 0 or grantee.rolname in ('anon', 'authenticated'));

select indexname, indexdef
from pg_indexes
where schemaname = 'public'
  and tablename = 'learning_courses'
  and indexname = 'learning_courses_instructor_updated_at_idx';
```

Expected: anonymous execution is false; authenticated execution is true; authenticated direct `INSERT` and `UPDATE` are false; the column-privilege query returns no browser mutation rows; public published-course reads remain governed by the existing RLS policy.

## Functional verification

Using a non-production test Instructor with an active Instructor capability and approved `instructor_profiles` row:

1. Create a draft through the RPC and confirm its `instructor_id` is the authenticated user, its status is `draft`, its currency is `NGN`, and its slug is generated by the database.
2. Create another course with the same title and confirm a distinct suffixed slug is generated.
3. Update the owner’s draft and confirm the slug does not change.
4. Attempt an update after changing status to `pending_review` through an owner-approved maintenance test; it must fail.
5. Confirm an unapproved applicant, a normal Learner, and `anon` cannot execute authoring RPCs successfully.
6. Confirm public published-course reads still work.

Do not use a browser table insert/update as a test; those paths are intentionally removed.

## Operational notes and correction strategy

This migration deliberately makes legacy direct browser course authoring and direct browser course approval unavailable. Do not restore the dropped policies or table mutation grants if an old prototype page stops working; that would restore the review-bypass risk. Use the new RPC-backed Learning application instead.

Because this is an authorization migration, do not attempt a broad rollback by restoring prior policies. If a post-deployment defect is discovered, prepare a separate forward-only corrective migration after identifying the exact live state. The migration does not delete courses or alter existing published rows.

If an execution fails in the opening preflight transaction, treat the migration as unapplied unless the transaction status is explicitly shown otherwise. The ACL inspection intentionally calls `aclexplode` only for non-null column ACL arrays; do not replace that guard with a fabricated empty `aclitem[]` value.

Future checkpoints will add curriculum, provider-neutral video references, rights declarations, submission, and atomic course review separately.
